# System Identity UI review, 2026-10-18

Version 0.3.2 makes the native System Identity window match the terminal menu's dark palette, monospaced title and cyan selection. Snapshots, Operations and Results separate the workflow. Results keeps messages and recovery paths until the window closes, and the footer keeps navigation, cancellation and Close available.

## Findings and fixes

- The previous wrapping controls could crowd the values table. Snapshot actions now use two rows, the values table has minimum column widths and horizontal scrolling, and operation choices scroll above a pinned Apply button.
- Native tab drawing left a white strip and clipped captions. The themed tab control paints the full strip and sizes its tabs from their text. Disabled button and checkbox captions also need explicit dim text to stay readable on dark backgrounds.
- Large fonts could squeeze the values table down to a few pixels and clip action captions. The minimum window size now grows with text size. Grid cells inherit the current font, and row/header heights follow font changes.
- Synchronous registry, adapter and file work could delay the UI before an asynchronous wait. Snapshot reads, file work, Apply and Restore now run on workers; review dialogs marshal back to the UI thread.
- Cancellation used to share the window's lifetime token, making later work unusable after cancellation. Each action now has its own token. Cancel leaves the window open for retry; Close waits for the current step and prevents another action from starting while it closes.
- A failed capture could replace saved state too early. Snapshots are validated and rendered before replacing the stored baseline/After reference. Expected and unexpected operation failures return controls to their ready state, keep prior data and open Results.
- Closing a window followed by Dispose could release resources twice. Lifetime and font disposal now have a guard, with repeated open/close coverage.

The review also traced the terminal handoff: the terminal draws its opening message before showing the native window, retains its selected tab and discards queued keys after return. Existing resizing and confirmation rules remain covered by the regression suite. Backend target validation, review/backup ordering and recovery checks remain in their existing layer.

## Evidence

The Release suite passed all 691 cases, with none skipped. Fifteen cases exercise the native window on an STA thread with a persistent Windows message loop and cross-thread control checks enabled. They cover three window sizes (760×540, 900×650 and 1180×800), simulated 125/150/200% scaling, 12/16-point fonts, an 8192-character value, inaccessible privileged options, failed/invalid captures, cancellation followed by retry, closing during work and repeated reopening/disposal.

Synthetic screenshots of Snapshots, Operations, Results and larger-font layouts were generated and visually inspected. No test applies identifier changes, renews DHCP, flushes DNS or cleans Roblox data. The full suite also checks the existing account, terminal, logo, comparison and backup behavior.

## Remaining manual checks

Simulated control scaling does not replace moving the real window between monitors with different DPI settings. High-contrast colors follow Windows settings, but high-contrast mode and screen-reader navigation still need a manual pass. Cancellation is cooperative: an in-flight native request may finish before the window closes. Real privileged operation/recovery checks remain outside this UI verification; see [system identity limits](system-identity.md#verification-limits).
